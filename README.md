# Pastelería y Catering X7 — Sistema Web de Gestión de Pedidos y Catálogo

Aplicación web con **Spring Boot 3.4.5**, **Thymeleaf**, **Spring Data JPA / Hibernate**, **PostgreSQL** (administrado con **pgAdmin**) y **Spring Validator**.

## 1. Requisitos

- Java 17 o superior
- PostgreSQL 15, 16 o 17 con pgAdmin 4
- No hace falta instalar Maven: el proyecto trae el wrapper (`mvnw` / `mvnw.cmd`)

## 2. Crear la base de datos en pgAdmin

1. Abre pgAdmin y conéctate a tu servidor PostgreSQL (puerto 5432).
2. Clic derecho en **Databases → Create → Database…**, escribe `pasteleria_x7` y guarda.
   También puedes ejecutar `database/01_crear_base_datos.sql` en el *Query Tool*.
3. **No crees las tablas a mano.** Hibernate las crea al iniciar la aplicación (`ddl-auto=update`).

## 3. Configurar la conexión

La conexión está en `src/main/resources/application.properties`. El usuario es `postgres` y la contraseña por defecto es `admin`:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/pasteleria_x7
spring.datasource.username=postgres
spring.datasource.password=${DB_PASSWORD:admin}
```

Si tu PostgreSQL usa otra contraseña, no hace falta editar el archivo: defínela en la terminal antes de ejecutar.

```bash
# Windows (cmd)
set DB_PASSWORD=tu_clave
# Linux / macOS
export DB_PASSWORD=tu_clave
```

```bash
# Windows
mvnw.cmd spring-boot:run
# Linux / macOS
./mvnw spring-boot:run
```

### Errores frecuentes

| Mensaje en consola | Causa | Solución |
|---|---|---|
| `password authentication failed for user "postgres"` | Contraseña incorrecta | Define `DB_PASSWORD` con tu contraseña (paso 3) |
| `database "pasteleria_x7" does not exist` | No se creó la base | Créala en pgAdmin (paso 2) |
| `Connection to localhost:5432 refused` | PostgreSQL apagado o en otro puerto | Inicia el servicio de PostgreSQL o corrige el puerto |

## 5. Modelo de datos y relaciones

```
usuario 1 ──── N pedido N ──── 0..1 producto
```

| Entidad | Tabla | Relación |
|---|---|---|
| `Usuario` | `usuario` | `@OneToMany(mappedBy = "usuario")`: un usuario registra muchos pedidos |
| `Producto` | `producto` | `@OneToMany(mappedBy = "producto")`: un producto aparece en muchos pedidos |
| `Pedido` | `pedido` | `@ManyToOne` hacia `Usuario` (FK `usuario_id`, obligatoria) y hacia `Producto` (FK `producto_id`, opcional: es NULL en catering y en pedidos personalizados) |

Restricciones en PostgreSQL: claves primarias `bigint generated by default as identity`; `fk_pedido_usuario` y `fk_pedido_producto`; `uk_usuario_email`, `uk_producto_nombre` y `uk_pedido_codigo`; y `CHECK` para `rol`, `tipo` y `estado` (enums `Rol`, `TipoPedido` y `EstadoPedido` guardados con `@Enumerated(EnumType.STRING)`). El dinero usa `numeric(10,2)` (`BigDecimal`) y las fechas usan `date` / `timestamp`.

## 6. Operaciones CRUD

| Entidad | Crear | Leer | Actualizar | Eliminar |
|---|---|---|---|---|
| Producto | Panel admin / `POST /api/productos` | Catálogo, panel admin con búsqueda / `GET /api/productos` | Editar en el panel / `PUT /api/productos/{id}` | Panel admin / `DELETE /api/productos/{id}` (bloqueado si tiene pedidos) |
| Pedido | `/pedido` y `/reservar` (cliente) | Panel del cliente (solo los suyos) y panel admin con filtro por estado / `GET /api/pedidos` | Estado y monto de la cotización / `PUT /api/pedidos/{id}` | Panel admin / `DELETE /api/pedidos/{id}` |
| Usuario | `/registro` | Inicio de sesión y paneles; pestaña **Clientes** del admin | `/cliente/perfil` (Mis datos) | — |

Los repositorios extienden `JpaRepository` y usan consultas derivadas (`findByEmailIgnoreCase`, `findByCategoriaAndNombreContainingIgnoreCase`, `findByEstadoOrderByIdDesc`, `countByProductoId`…), consultas JPQL (`@Query`) y `@EntityGraph` para traer el usuario y el producto de cada pedido en una sola consulta.

## 7. Validación (Spring Validator)

- Anotaciones en las entidades y formularios: `@NotBlank`, `@NotNull`, `@Size`, `@Email`, `@Pattern`, `@Min`, `@Max`, `@DecimalMin`, `@Digits` y `@Future`.
- Los controladores reciben los datos con `@Valid` + `BindingResult`. Las reglas que consultan la base de datos (correo o nombre repetido, producto disponible) se agregan al mismo `BindingResult` con `rejectValue`.
- Las vistas muestran cada mensaje debajo de su campo con `th:errors` y la clase `is-invalid` de Bootstrap.
- Los mensajes están centralizados en `src/main/resources/messages.properties`.
- La API REST responde `400 Bad Request` con el detalle de cada campo en JSON.
- Los formularios validados llevan `novalidate`, para que los mensajes que se vean sean los de Spring y no los del navegador. Si quitas `novalidate`, el navegador también valida con los atributos HTML5 (`required`, `min`, `maxlength`…).

## 8. API REST

Importa `postman/X7-API.postman_collection.json` en Postman y ejecuta primero **Iniciar sesión (admin)**: Postman guarda la cookie de sesión.

| Método | Ruta | Acceso | Respuestas |
|---|---|---|---|
| POST | `/api/auth/login` | Público | 200, 400, 401 |
| GET | `/api/auth/sesion` | Con sesión | 200, 401 |
| POST | `/api/auth/logout` | Con sesión | 204 |
| GET | `/api/productos?nombre=&categoria=` | Público | 200 |
| GET | `/api/productos/{id}` | Público | 200, 404 |
| POST | `/api/productos` | Admin | 201, 400, 401, 403, 409 |
| PUT | `/api/productos/{id}` | Admin | 200, 400, 404, 409 |
| DELETE | `/api/productos/{id}` | Admin | 204, 404, 409 |
| GET | `/api/pedidos?estado=` | Admin: todos · Cliente: los suyos | 200, 400, 401 |
| GET | `/api/pedidos/{id}` | Admin o dueño | 200, 403, 404 |
| PUT | `/api/pedidos/{id}` | Admin | 200, 400, 404 |
| DELETE | `/api/pedidos/{id}` | Admin | 204, 404 |

## 9. Comprobar la persistencia en pgAdmin

Abre el *Query Tool* sobre `pasteleria_x7` y ejecuta `database/03_consultas_verificacion.sql`: lista las tablas, sus restricciones, los pedidos con su cliente y su producto (JOIN), los pedidos por estado y los clientes con su cantidad de pedidos.
`database/02_esquema_referencia.sql` documenta el esquema que genera Hibernate.

## 10. Estructura

```
src/main/java/com/x7/pasteleria
├── X7Application.java
├── config/DatosIniciales.java        ← datos de partida (solo si la BD está vacía)
├── model/                            ← entidades JPA y enums
├── repository/                       ← interfaces Spring Data JPA
├── dto/                              ← formularios y cuerpos JSON validados
└── controller/                       ← controladores web (Thymeleaf)
    └── api/                          ← controladores REST (JSON)
src/main/resources
├── application.properties            ← conexión a PostgreSQL
├── messages.properties               ← mensajes de validación
├── templates/                        ← vistas Thymeleaf
└── static/                           ← CSS y JavaScript
database/                             ← scripts SQL para pgAdmin
postman/                              ← colección de pruebas de la API
```
