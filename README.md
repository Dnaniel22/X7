# Pastelería y Catering X7 — Sistema Web de Gestión de Pedidos y Catálogo

Aplicación web con **Spring Boot 3.4.5**, **Thymeleaf**, **Spring Data JPA / Hibernate**, **PostgreSQL** (administrado con **pgAdmin**), **Spring Validator**, **Spring Security** y **JWT**.

- El **sitio web** usa Spring Security con formulario de login, sesión, roles (`CLIENTE` y `ADMINISTRADOR`) y contraseñas cifradas con BCrypt.
- La **API REST** (`/api/**`) se protege con **JSON Web Tokens**: se pide un token con `POST /api/auth/login` y se envía en la cabecera `Authorization: Bearer <token>`.

## 1. Requisitos

- Java 17 o superior
- PostgreSQL 15, 16 o 17 con pgAdmin 4
- No hace falta instalar Maven: el proyecto trae el wrapper (`mvnw` / `mvnw.cmd`)

## 2. Crear la base de datos en pgAdmin

1. Abre pgAdmin y conéctate a tu servidor PostgreSQL (puerto 5432).
2. Clic derecho en **Databases → Create → Database…**, escribe `pasteleria_x7` y guarda.
   También puedes ejecutar `database/01_crear_base_datos.sql` en el *Query Tool*.
3. **No crees las tablas a mano.** Hibernate las crea al iniciar la aplicación (`ddl-auto=update`).

## 3. Configurar la conexión

La conexión está en `src/main/resources/application.properties`. El usuario es `postgres` y la contraseña por defecto es `admin`:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/pasteleria_x7
spring.datasource.username=postgres
spring.datasource.password=${DB_PASSWORD:admin}
```

Si tu PostgreSQL usa otra contraseña, no hace falta editar el archivo: defínela en la terminal antes de ejecutar.

```bash
# Windows (cmd)
set DB_PASSWORD=tu_clave
# Linux / macOS
export DB_PASSWORD=tu_clave
```

### Errores frecuentes

| Mensaje en consola | Causa | Solución |
|---|---|---|
| `password authentication failed for user "postgres"` | Contraseña incorrecta | Define `DB_PASSWORD` con tu contraseña (paso 3) |
| `database "pasteleria_x7" does not exist` | No se creó la base | Créala en pgAdmin (paso 2) |
| `Connection to localhost:5432 refused` | PostgreSQL apagado o en otro puerto | Inicia el servicio de PostgreSQL o corrige el puerto |
| La API responde `401` con "El token expiró" | Pasaron más de 60 minutos desde el login | Vuelve a ejecutar `POST /api/auth/login` |
| Error 403 al enviar un formulario | La sesión expiró y el token CSRF ya no vale | Recarga la página e inicia sesión de nuevo |

## 5. Modelo de datos y relaciones

```
usuario 1 ──── N pedido N ──── 0..1 producto
```

| Entidad | Tabla | Relación |
|---|---|---|
| `Usuario` | `usuario` | `@OneToMany(mappedBy = "usuario")`: un usuario registra muchos pedidos |
| `Producto` | `producto` | `@OneToMany(mappedBy = "producto")`: un producto aparece en muchos pedidos |
| `Pedido` | `pedido` | `@ManyToOne` hacia `Usuario` (FK `usuario_id`, obligatoria) y hacia `Producto` (FK `producto_id`, opcional: es NULL en catering y en pedidos personalizados) |

Restricciones en PostgreSQL: claves primarias `bigint generated by default as identity`; `fk_pedido_usuario` y `fk_pedido_producto`; `uk_usuario_email`, `uk_producto_nombre` y `uk_pedido_codigo`; y `CHECK` para `rol`, `tipo` y `estado` (enums `Rol`, `TipoPedido` y `EstadoPedido` guardados con `@Enumerated(EnumType.STRING)`). El dinero usa `numeric(10,2)` (`BigDecimal`) y las fechas usan `date` / `timestamp`.

## 6. Operaciones CRUD

| Entidad | Crear | Leer | Actualizar | Eliminar |
|---|---|---|---|---|
| Producto | Panel admin / `POST /api/productos` | Catálogo, panel admin con búsqueda / `GET /api/productos` | Editar en el panel / `PUT /api/productos/{id}` | Panel admin / `DELETE /api/productos/{id}` (bloqueado si tiene pedidos) |
| Pedido | `/pedido` y `/reservar` (cliente) | Panel del cliente (solo los suyos) y panel admin con filtro por estado / `GET /api/pedidos` | Estado y monto de la cotización / `PUT /api/pedidos/{id}` | Panel admin / `DELETE /api/pedidos/{id}` |
| Usuario | `/registro` | Inicio de sesión y paneles; pestaña **Clientes** del admin | `/cliente/perfil` (Mis datos); el admin activa o desactiva cuentas | — |

Los repositorios extienden `JpaRepository` y usan consultas derivadas (`findByEmailIgnoreCase`, `findByCategoriaAndNombreContainingIgnoreCase`, `findByEstadoOrderByIdDesc`, `countByProductoId`…), consultas JPQL (`@Query`) y `@EntityGraph` para traer el usuario y el producto de cada pedido en una sola consulta.

## 7. Validación (Spring Validator)

- Anotaciones en las entidades y formularios: `@NotBlank`, `@NotNull`, `@Size`, `@Email`, `@Pattern`, `@Min`, `@Max`, `@DecimalMin`, `@Digits` y `@Future`.
- Los controladores reciben los datos con `@Valid` + `BindingResult`. Las reglas que consultan la base de datos (correo o nombre repetido, producto disponible) se agregan al mismo `BindingResult` con `rejectValue`.
- Las vistas muestran cada mensaje debajo de su campo con `th:errors` y la clase `is-invalid` de Bootstrap.
- Los mensajes están centralizados en `src/main/resources/messages.properties`.
- La API REST responde `400 Bad Request` con el detalle de cada campo en JSON.
- Los formularios validados llevan `novalidate`, para que los mensajes que se vean sean los de Spring y no los del navegador. Si quitas `novalidate`, el navegador también valida con los atributos HTML5 (`required`, `min`, `maxlength`…).
- La contraseña del registro (`RegistroForm`) debe tener de 8 a 60 caracteres y combinar mayúsculas, minúsculas, números y un símbolo.

## 8. Seguridad (Spring Security)

Toda la configuración está en `security/SecurityConfig.java`. Hay **dos cadenas de filtros** (`SecurityFilterChain`):

| Cadena | Rutas | Autenticación | Estado | Errores |
|---|---|---|---|---|
| API (`@Order(1)`) | `/api/**` | JWT en `Authorization: Bearer` | Sin sesión (`STATELESS`), sin CSRF | JSON `401` / `403` |
| Web (`@Order(2)`) | todo lo demás | Formulario de login (`/login`) | Sesión con cookie `JSESSIONID`, con CSRF | Redirección a `/login` o página `403` |

**Piezas**

| Clase | Qué hace |
|---|---|
| `SecurityConfig` | Reglas de acceso por ruta y rol, login, logout, `PasswordEncoder` (BCrypt) y `AuthenticationManager` |
| `UsuarioDetailsService` | Implementa `UserDetailsService`: busca al usuario por correo en PostgreSQL |
| `UsuarioPrincipal` | Implementa `UserDetails`: correo, hash, rol (`ROLE_CLIENTE` / `ROLE_ADMINISTRADOR`) y si la cuenta está activa |
| `SesionSeguridad` | Inicia sesión al crear una cuenta y actualiza el nombre en sesión al editar el perfil |
| `jwt/JwtService` | Genera y valida los tokens (firma HMAC-SHA con `jwt.secreto`) |
| `jwt/JwtAuthenticationFilter` | Lee el token de cada petición a `/api/**` y registra al usuario |
| `jwt/ErroresApiSeguridad` | Respuestas JSON `401` y `403` de la API |

**Permisos del sitio web**

| Ruta | Visitante | Cliente | Administrador |
|---|---|---|---|
| `/`, `/catalogo`, `/login`, `/registro` | ✅ | ✅ | ✅ |
| Ver `/pedido` y `/reservar` | ✅ | ✅ | ✅ |
| Enviar `/pedido` y `/reservar` (POST) | ➜ login | ✅ | ❌ 403 |
| `/cliente/**` (Mi panel, Mis datos) | ➜ login | ✅ | ❌ 403 |
| `/admin/**` (pedidos, productos, clientes) | ➜ login | ❌ 403 | ✅ |

**Detalles**

- **Login y logout:** el formulario `/login` lo procesa Spring Security (`usernameParameter("email")`). Cada rol entra a su panel. `POST /logout` cierra la sesión y borra la cookie.
- **Contraseñas:** se guardan con `BCryptPasswordEncoder` (hash de 60 caracteres que empieza con `$2a$10$`).
- **Cuentas activas:** en la pestaña **Clientes** del panel admin se puede desactivar una cuenta. Una cuenta desactivada no puede iniciar sesión (`UserDetails.isEnabled()`) ni usar un token que ya tenía.
- **Vistas:** el menú usa `sec:authorize` (muestra opciones según el rol) y `sec:authentication` (nombre del usuario), de `thymeleaf-extras-springsecurity6`.
- **CSRF:** activo en el sitio web. `th:action` agrega el token oculto a cada formulario POST.
- **403:** un usuario con sesión que abre una ruta de otro rol ve `templates/error/403.html`.

## 9. JWT en la API REST

**Flujo**

1. `POST /api/auth/login` con `{"email": "admin@x7.com", "password": "Admin123!"}`.
2. La API comprueba la contraseña con BCrypt y responde:
   ```json
   {
     "token": "eyJhbGciOiJIUzM4NCJ9.eyJzdWIiOiJhZG1pbkB4Ny5jb20iLCJpZCI6MSwibm9tYnJlIjoi...",
     "tipo": "Bearer",
     "expiraEnSegundos": 3600,
     "usuario": { "id": 1, "nombre": "Administrador X7", "email": "admin@x7.com", "rol": "ADMINISTRADOR" }
   }
   ```
3. Las siguientes peticiones envían la cabecera `Authorization: Bearer <token>`.
4. `JwtAuthenticationFilter` valida la firma, el emisor y la expiración en cada petición. Si el token es válido, Spring Security aplica las reglas `hasRole(...)`.

**Qué lleva el token:** correo (`sub`), `id`, `nombre`, `rol`, emisor (`iss = pasteleria-x7`), fecha de emisión (`iat`) y de vencimiento (`exp`). Se puede leer en https://jwt.io, pero no se puede modificar sin la clave secreta: si alguien cambia un dato, la firma deja de coincidir y la API responde 401.

**Configuración** (`application.properties`):

```properties
jwt.secreto=${JWT_SECRET:...}      # clave Base64 de al menos 256 bits
jwt.expiracion-minutos=60
```

**Respuestas de seguridad de la API**

| Caso | Respuesta |
|---|---|
| Sin token en una ruta protegida | `401` "Debes enviar un token…" |
| Token con firma alterada o mal formado | `401` "El token no es válido…" |
| Token vencido | `401` "El token expiró…" |
| Token de una cuenta desactivada | `401` "La cuenta está desactivada." |
| Token válido pero rol sin permiso | `403` "Tu rol no tiene permiso…" |

**Probar con Postman:** importa `postman/X7-API.postman_collection.json`, ejecuta **Iniciar sesión (admin)** y **Iniciar sesión (cliente)** (guardan los tokens en variables) y luego cualquier petición. La carpeta **4. Seguridad** muestra los casos 401 y 403.

**Probar con curl:**

Funciona igual en la consola de Windows (cmd) y en Linux/macOS:

```bash
curl -X POST http://localhost:8080/api/auth/login -H "Content-Type: application/json" -d "{\"email\":\"admin@x7.com\",\"password\":\"Admin123!\"}"

curl http://localhost:8080/api/pedidos -H "Authorization: Bearer TOKEN"
```

El primer comando devuelve el token; cópialo en lugar de `TOKEN` en el segundo.

## 10. API REST

Importa `postman/X7-API.postman_collection.json` en Postman y ejecuta primero **Iniciar sesión (admin)**: Postman guarda el token y lo envía en las demás peticiones.

| Método | Ruta | Acceso | Respuestas |
|---|---|---|---|
| POST | `/api/auth/login` | Público | 200 (token), 400, 401 |
| GET | `/api/auth/perfil` | Token de cualquier rol | 200, 401 |
| GET | `/api/productos?nombre=&categoria=` | Público | 200 |
| GET | `/api/productos/{id}` | Público | 200, 404 |
| POST | `/api/productos` | Token ADMINISTRADOR | 201, 400, 401, 403, 409 |
| PUT | `/api/productos/{id}` | Token ADMINISTRADOR | 200, 400, 401, 403, 404, 409 |
| DELETE | `/api/productos/{id}` | Token ADMINISTRADOR | 204, 401, 403, 404, 409 |

## 12. Estructura

```
src/main/java/com/x7/pasteleria
├── X7Application.java
├── config/DatosIniciales.java        ← datos de partida y cifrado de contraseñas antiguas
├── security/                         ← Spring Security: SecurityConfig, UserDetailsService, UserDetails
│   └── jwt/                          ← JwtService, filtro JWT y respuestas 401/403 de la API
├── model/                            ← entidades JPA y enums
├── repository/                       ← interfaces Spring Data JPA
├── dto/                              ← formularios y cuerpos JSON validados
└── controller/                       ← controladores web (Thymeleaf)
    └── api/                          ← controladores REST (JSON)
src/main/resources
├── application.properties            ← conexión a PostgreSQL y configuración JWT
├── messages.properties               ← mensajes de validación
├── templates/                        ← vistas Thymeleaf (error/403.html: acceso denegado)
└── static/                           ← CSS y JavaScript
database/                             ← scripts SQL para pgAdmin
postman/                              ← colección de pruebas de la API
```
